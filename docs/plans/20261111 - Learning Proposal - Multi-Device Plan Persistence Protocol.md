# Learning Proposal: Multi-Device Plan Persistence & Repository Dual-Write Protocol

## 1. Classification & Scope
* **Type:** Workspace Rule (Invariable Behavioral Guardrail & Protocol)
* **Target Files:**
  1. `.antigravityrules` — Rule 14 under `DOMAIN 4: AGENT WORKFLOW, IDE HYGIENE & QUALITY VERIFICATION`
  2. `AGENTS.md` — Section `2.29` under `NON-NEGOTIABLE BUSINESS RULES`
  3. `.agents/rules/agent-workflow.md` — Section 3 (`Standard Plan Artifact Naming Convention & Repository Dual-Write Protocol`)
* **Trigger Command:** `/learn`
* **Scope:** Universal across all implementation plans, side quest plans, and architectural design artifacts generated by Antigravity or any agent in the TopsCore workspace.

---

## 2. Rationale & Problem Statement
When developing across multiple laptops and workstations, implementation plans and design decisions must remain accessible regardless of which physical machine is currently active. 

Previously, plan artifacts were stored exclusively in the machine's local user directory:
```text
C:\Users\<User>\.gemini\antigravity\brain\<conversation-id>\
```
Because this folder sits outside the Git repository and is isolated to a single local user profile, switching to a different laptop rendered past plans and active milestone scopes inaccessible.

The user explicitly commanded:
> *"saya ingin agar saat buka laptop lain, plan yang ada bisa diakses"*
> *"/learn masukkan aturan plan ini"*

To guarantee 100% plan persistence, portability, and cross-device availability via Git sync (`git push` & `git pull`), the agent MUST dual-write all plans directly to `docs/plans/` in the repository while maintaining an interactive mirror in the active brain session.

## 4. Verification & Confirmation Protocol
1. Running `scripts/verify_plan_migration.mjs` programmatically validates that:
   - All files in `docs/plans/` adhere to `YYYYMMDD - <Plan Name>.md`.
   - `.agents/rules/agent-workflow.md`, `AGENTS.md`, and `.antigravityrules` maintain the exact Dual-Write tokens.
2. Upon user clicking **Proceed** or giving explicit approval, the changes will be permanently ratified across all governance files.
